# Maintain Server Containers v0.4.0

**Release date:** 14 October 2026
**Installable skill:** `skills/maintain-server-containers/`
**Previous release:** `v0.3.0`

## What's new

- **PR #25: First real-server read-only acceptance improvements.** Add standard-library-only `scripts/doctor.py` to check Python/PyYAML readiness in the exact selected interpreter without installing anything. YAML readiness and JSON-policy readiness are reported separately.
- **PR #25: Compose source preflight.** Add `scripts/compose_preflight.py` for exact ordered source-file presence and optional `docker compose config --quiet` rendering on the deployment filesystem. Missing files, required interpolation variables and unverified source parity remain blocking.
- **PR #25: Broader agent audit coverage.** Explicitly reconcile all discovered Compose projects and unmanaged/unlabelled containers, external-admin `NO_TOUCH` resources, cross-project networks and composite service/group identities. The bundled CLI itself still inspects only selected Compose service identities.
- **PR #26: Clearer safety documentation and outputs.** Remove stale server-side PyYAML install suggestions; distinguish machine status, blocker codes, readiness flags and agent-level findings from update authorization. Require a concise runtime-to-policy coverage summary with unknown values marked `NOT VERIFIED`.
- **PR #26: Cross-platform synthetic test stability.** Explicitly close SQLite handles before renaming or deleting temporary fixtures, fix POSIX-specific path assumptions, and read release text as UTF-8. Add a Windows offline GitHub Actions job alongside existing Linux CI.

## Capability boundary

`maintenance.py` remains **read-only** (`validate`, `audit`, `status`, `plan`). There is **no bundled deterministic production Docker mutation executor**. The skill defines bounded agent-operated workflows for expressly authorized operations but never grants an update based solely on preflight, image metadata, policy validation or a reported snapshot.

Compose source render does not prove live topology equality; backup snapshot metadata does not prove successful restore. Experimental cryptographic and Restic CI only exercise synthetic local fixtures, **not** independently secured off-host backups, live production recovery or migration rollback. External administrators retain `EXTERNAL_ADMIN / NO_TOUCH`.

## Upgrade safety

Do not install from `main` or an unreviewed PR. After the `v0.4.0` GitHub Release exists, use its exact tag, verify both plugin manifests and `skills/maintain-server-containers/VERSION` equal `0.4.0`, back up the existing `v0.3.0` user-scope installation outside active skill discovery paths, replace only the canonical skill folder, and verify the installed files and offline checks. No live server, Docker, secrets, persistent data or backups should change during skill installation. Roll back the local installation if verification fails.
