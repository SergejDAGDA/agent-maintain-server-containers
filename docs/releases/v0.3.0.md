# Maintain Server Containers v0.3.0

**Release date:** 13 October 2026  
**Installable skill:** `skills/maintain-server-containers/`  
**Previous release:** `v0.2.0`

## What's new

- Hardened **portable v1 policy validation**: undocumented top-level, service and section settings now fail closed. Existing consumers relying on project-specific extension fields must first map them explicitly or use a reviewed native project policy.
- Strict native policy revision types and synthetic runtime input validation.
- **Less sensitive read-only Docker inspection**: select only container identity, configured image, running/health state, and relevant mount metadata rather than requesting entire `docker inspect` contents.
- Provider-neutral experimental recovery descriptor and source-pinned, read-only evidence contracts.
- Synthetic-only local encrypted Restic backup/restore of SQLite attachments and an isolated PostgreSQL two-service group, with signed-witness, replay, continuity, monotonic CAS and end-to-end failure/refusal scenarios **H20–H31**.
- Dedicated architecture/security audit and a verifiable `VERSION` file inside the installable skill folder.

## Validation

The final PR #22 baseline passed **373/373** automated tests and the disposable Docker Compose recovery workflow, including H31 and owned resource cleanup. This release's own workflow must separately pass on its exact commit before the tag is published.

## Capability boundary — important

The bundled Python `maintenance.py` supports only **read-only** `validate`, `audit`, `status`, and `plan`. The `SKILL.md` instructions can guide a properly authorized agent through bounded manual operations, but there is **no bundled deterministic production Docker mutation executor**.

All newly added cryptographic and local Restic tests are synthetic CI research. They **do not prove off-host independence**, protected live backups, safe migrations, tenant-data restore, or production recovery readiness. No live server or backup has been modified during this release work.

## Upgrade safety

Install or update the canonical `skills/maintain-server-containers/` folder from the exact `v0.3.0` tag, not an unrelated cache or a working branch. Back up an existing installation before replacement and do not overwrite project-specific policy or local configuration. Confirm the installed `VERSION` is `0.3.0`, the script and references folders are intact, and the existing example-policy checks pass. A GitHub release does **not** automatically update any installed copy.
